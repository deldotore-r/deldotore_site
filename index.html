Selected investigations

Details are generalized and figures rounded to respect client confidentiality.

  • Ingestion tasks taking hours, with no errors

    Root cause confirmed

    Symptom
    A pipeline kept reporting success while tasks that should take minutes ran for more than four hours. No errors, no alerts.
    Evidence
    I read the table's Iceberg metadata directly from S3, sampled the commit process through /proc (it sat in I/O wait, not on CPU), and matched commit counts against run history in the Airflow metadata database.
    Cause
    Two years of tiny commits with no snapshot expiration. The table's metadata had grown to more than 5,000 times the size of its data, and every commit had to read and rewrite it.
    Outcome
    An investigation report with a retention-based remediation plan. A follow-up scan found dozens of other tables with the same pattern.

    Tools: AWS CLI, kubectl, Python (fastavro, psycopg2)

  • Spark jobs failing seconds after landing on a new node

    Root cause confirmed, fix in progress

    Symptom
    Bursts of Spark drivers failed with network timeouts whenever the cluster scaled up. Relaunching them worked, so the failures looked random.
    Evidence
    I measured newly created nodes live and reconstructed what each node did from the EKS API server audit logs.
    Cause
    New nodes reported Ready after about 13 seconds, but pod networking took 2 to 3.5 minutes to converge. Drivers scheduled in that window timed out after 16 seconds.
    Outcome
    A written analysis of four mitigations for the platform decision: a startup taint released by a real network check, spare capacity, automatic retries, and faster network convergence.

    Tools: kubectl, AWS CLI, CloudWatch Logs, Cluster Autoscaler and Calico configuration

  • A morning check for resources nobody is using

    Runs every morning

    Problem
    Waste and stuck work only came to light when someone happened to notice it. There was no routine check across environments.
    Built
    A written morning protocol of 21 checks, backed by a Python command-line tool that needs nothing but kubectl and the AWS CLI. It covers crash-looping and OOM-killed pods, pods stuck pending or terminating, zombie Spark pods, orphaned EMR clusters, failed and stuck DAG runs, and orphaned Hive Metastore locks.
    Found
    Among other things, three idle EMR clusters with 18 instances and no auto-termination, and DAG runs stuck for almost a month.
    Outcome
    Part of my daily routine, and proposed to the team as a standard platform check.

    Tools: Python standard library, kubectl, AWS CLI, Airflow metadata database

How I work

  • Verify before concluding. My write-ups separate what I observed directly from what I infer.
  • Command line first. Investigations can be repeated step by step, by me or by anyone else.
  • One change at a time. In production, nothing changes until the evidence is in, and then only one thing at a time.
  • Write it down. Runbooks, protocols and incident reports, so knowledge doesn't stay in one head.
